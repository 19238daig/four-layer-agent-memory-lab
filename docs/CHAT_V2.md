# 聊天演示 V2

打开 `http://127.0.0.1:8010/?view=meal`，发送普通消息即可。点击“新会话”会默认使用历史记忆。需要做对照时，点“新会话”右侧的下拉箭头，选择“新建无记忆对照”。切换引擎也会开启新会话，左侧可以切回旧的聊天。

| 演示目的 | 操作 | 核验 |
| --- | --- | --- |
| 自动记忆 | 选择“并排对话”，发送“以后晚饭我喜欢吃辣，预算500块，热量不超过1000千卡。” | 两组分别显示已更新记忆 |
| 跨会话使用 | 点击“新会话”，只问“晚上吃什么好？” | 两组使用辣度1～2、预算500元、热量上限1000千卡，推荐来源可展开 |
| 无历史对照 | 点“新会话”右侧下拉箭头，选择“新建无记忆对照”，发同一个问题 | 新会话不读写长期记忆，演示默认值为120元、600～700千卡、不辣 |
| Deep Agents 单独使用 | 选择 Deep Agents，发送“我家猫叫年糕。”新开会话问“我家猫叫什么？” | 从该引擎的文件记忆找回名字和原话 |
| 临时覆盖 | 长期记住不辣后，说“今天这顿想吃辣，预算200，晚饭有什么菜？” | 当轮条件只在查询中覆盖，后续独立会话仍读取长期偏好 |

回复下的“查看记忆与来源”默认显示本轮筛选条件和关联原话。“来源记录”可展开原话或选餐证据，“技术详情”保留记忆版本、模型上下文、工具及 SQL 查询轨迹。选餐回答使用只读 SQLite 菜单数据快照，候选和数值由业务查询核验。四层引擎通过模型提取意图与记忆，选餐使用固定公式查询。Deep Agents 通过真实框架读取文件，并独立调用记忆与查询工具。

同一餐次的新热量要求会替换旧范围。“热量超过500千卡”表示严格大于500，并清除原热量上限。“至少500千卡”包含500。明确说“只改热量下限”时保留未修改的上限。范围冲突时，请重新说明上下限。

点会话条目右侧的垃圾桶并确认，可从列表删除对话。该对话不能继续打开或发送消息，已经学到的偏好及其关联来源仍保留。

聊天根目录是 `data/memory_v2/meal/workspaces/<空间名>/`。默认空间叫 `meal-demo`。聊天侧栏的“记忆文件位置”显示当前空间的完整路径。原来的哈希目录会在服务启动时按空间名改名。重名时会追加 `-2`、`-3`，每个空间仍保留各自的会话和记忆。

查看当前长期记忆时，四层记忆先打开 `four_layer/knowledge/chat-index.md`，再点其中的“当前主题”。Deep Agents 直接打开 `deep_agents/AGENTS.md`。对应引擎首次保存长期记忆后才会生成这两个入口文件。

| 目录 | 内容 |
| --- | --- |
| `four_layer/transcripts`、`notes` | JSONL 原话与工具结果，JSON 记忆笔记 |
| `four_layer/knowledge`、`chat_versions` | Markdown 主题页和 JSON 版本清单 |
| `four_layer/contexts` | 真实模型上下文与标注未发送模型的选餐材料 |
| `deep_agents/AGENTS.md`、`knowledge`、`revisions` | Deep Agents 当前长期记忆、主题文件及历史版本 |
| `deep_agents/checkpoints` | 每个会话的 JSON 检查点、已完成状态指针 |
| `sessions`、`runs` | 会话配置和真实运行事件 |

业务库与本轮业务快照在 `data/meal_lab/`。旧 SQLite 记忆数据库仍可作为归档查阅。新聊天的四层引擎可从已校准的旧偏好按餐次初始化。已校验来源的旧 Deep Agents 文件已导入 `deep_agents/legacy/` 供回查。新 Deep Agents 聊天从自己在聊天中形成的记忆开始，避免把旧比较结果算作新引擎已经学到的偏好。

记忆目录面向本地单进程。会话历史和检查点可在重启后恢复。中断的运行会被标明，继续聊天从最近完成的检查点开始。运行统计采用模型服务实际返回的 token，缺失时显示未提供。并排模式为独立运行观察，两组的调用数和框架提示不同。
